# 代码理解与答辩准备

## 1. 先掌握整体流程

控制台菜单或 Qt 按钮接收输入，调用 `ATM`。`ATM` 检查登录状态和业务条件，调用当前 `BankCard` 修改余额或密码，更新交易记录，最后保存文本文件。界面根据返回的 `bool` 和 `message()` 显示结果。

Qt 界面不自己加减余额。相同业务只有一套实现，因此控制台和 GUI 的取款规则、密码规则相同。

## 2. Money：为什么金额存整数分

`0.1` 这样的十进制小数在二进制浮点中可能不能精确表示。我们将 `200.50` 解析成 `20050` 分，余额的加减都是整数运算。

`parse_amount(text, cents)` 返回输入是否合法；成功时通过引用参数 `cents` 传回金额。按字符逐个读取，拒绝负数、字母、超过两位的小数和零。`format_money` 将分显示为两位小数的元。

`MAX_BALANCE` 是模拟系统金额范围，减少输入错误造成的不合理数值，不是银行的真实规则。

## 3. BankCard：封装

卡号、密码、余额和初始余额是私有成员。构造函数给对象设置初值；公有函数提供查询、密码验证和存取款操作。

`const` 成员函数表示函数不会修改对象的数据。`const std::string&` 避免复制字符串，同时不允许修改传入的字符串。`get_password()` 只供文本保存使用，窗口不显示它。

初始余额用于曲线的第一个点。修改余额不改变初始余额。

## 4. ATM：管理多个账户与登录状态

`vector<BankCard>` 保存账户，`vector<Transaction>` 保存所有账户的交易。`current_index_` 为 -1 表示未登录，登录成功后保存对应账户的下标。

`current_card()` 返回当前账户的只读指针，未登录返回 `nullptr`。显示层通过它读取卡号、余额，不直接写账户数据。

`transact(amount, is_deposit)` 合并存款和取款共有的步骤。存款和取款仍有不同条件：取款必须是 10000 分的整数倍，并且余额足够。

操作前复制一份当前银行卡，修改后保存。如果保存失败，恢复刚才的银行卡，并移除新记录。因此界面不会报告成功却留下未保存的余额。

保存到同一个文本文件，账户行以 `CARD` 开头，交易行以 `RECORD` 开头。时间字符串带空格，用标准库 `quoted` 加引号保存和读取。先写 `.tmp` 再替换原文件，处理普通写入失败即可，没有数据库、加密、并发服务等复杂设计。

`load()` 首次找不到文件时创建三个演示账户；已有文件格式错误时提示错误，不重建覆盖。重启时不恢复登录状态，但恢复余额、密码和记录。

`current_records()` 按卡号筛选本账户记录。`balance_history()` 返回初始余额以及每笔交易后的余额，曲线不会使用写死的演示数据。

## 5. 控制台：普通 C++ 菜单

`main_console.cpp` 用循环显示菜单，`getline` 按行读取。菜单和金额都先作为字符串读取，避免输入字母使 `cin` 进入失败状态而无限循环。

输入结束时退出循环，因此终端关闭输入或输入文件读完不会卡死。控制台密码输入是普通文本；图形界面的密码框会隐藏输入。

控制台用 `show_menu` 统一显示页面，将最近一次操作的信息保存在字符串 `result` 中。下一轮循环清屏、显示菜单和结果，存取款结果包含操作金额和当前余额。交易记录独立显示，每页最多 5 笔，用页号计算当前记录下标，输入 1 上一页、2 下一页，回车返回。

清屏输出 `\033[2J\033[H`：前一段清除当前屏幕，后一段将光标移到左上角。`isatty` 检查输入输出是否连接终端；输出到文件或管道、或终端类型为 `dumb` 时不清屏。这里使用 WSL/Linux 的 `unistd.h`，没有引入额外终端库。

程序开始交互时输出 `\033[?1049h` 进入备用屏幕，这个屏幕不使用普通命令行的滚动历史。正常退出时输出 `\033[?1049l` 恢复原屏幕。Ctrl+C 或 SIGTERM 退出也会先恢复屏幕：`signal` 登记简单的处理函数，函数用 `write` 写出固定的恢复序列，再结束程序；`sig_atomic_t` 是用于信号处理的小型状态标志。没有修改终端的键盘输入模式。

## 6. Qt：只理解这里实际使用的内容

- `QApplication`：管理图形程序事件循环，`app.exec()` 等待点击、键盘和重绘事件。
- `QWidget`：基础窗口组件。`ATMWindow` 是主窗口，`BalanceChart` 是自定义绘图组件。
- `QVBoxLayout`、`QFormLayout`、`QGridLayout`：安排控件的位置，不需要手工计算所有按钮坐标。
- `QStackedWidget`：两个页面共用一个窗口，登录和退卡时切换页面。
- `QLineEdit`：输入框；密码框设置 `Password` 回显模式。
- `connect`：将控件发出的信号连接到处理函数。例如登录按钮发出 `clicked`，调用 `ATMWindow::login()`。
- 简单 lambda：`[this]` 让小段按钮处理代码使用当前窗口成员；`[this, i]` 还记住按钮编号。这里只用于 Qt 的必要连接，不用于构建复杂框架。
- `QDialog::exec()`：显示模态对话框，用户确认返回 `Accepted`，取消则不执行业务。
- 父子对象：`new QLabel(..., parent)` 等控件交给 Qt 的父对象管理，窗口销毁时自动销毁子控件，不需要逐个 `delete`。

界面函数的内容大多是建控件、建布局和连接按钮。真正的业务仍在 `ATM` 和 `BankCard`。

校园主题界面仍使用 Qt Widgets，没有额外框架。`resources.qrc` 将 `assets/campus.jpg` 编译为资源，程序通过 `:/images/campus.jpg` 加载。`ATMWindow::paintEvent` 将原照片按比例铺满，并计算需要裁切的原图范围，然后叠加柔和遮罩；原图片文件没有被裁剪或修改。

`resizeEvent` 在窗口尺寸变化时调用 `position_content`：以 1080×720 为基准，用宽度比与高度比中较小的一项作为统一放大比例，范围为 1～2.5。登录面板基础宽度为 450，账户面板为 660，字体、控件、图标、间距和阴影一起放大；小窗口最低为 640×620。登录面板在宽窗口靠左，在较小窗口居中，账户操作面板始终居中。面板内部仍使用布局管理器。

`scale_widgets` 保存控件的原始样式和最小尺寸，以及布局的边距和间距，每次从原值计算。因此缩回普通窗口时能够恢复原尺寸，不会反复放大。Qt 的 `QVariant` 属性保存这些原值；`scaled_style` 用 `QRegularExpression` 找到样式中的像素数值并乘以比例。弹窗也使用同一个比例。曲线通过 `QPainter::scale` 统一放大文字与坐标，在逻辑尺寸上绘制。

`QGraphicsDropShadowEffect` 给面板增加阴影；按钮的 hover 和 pressed 样式分别处理悬停与按下反馈。小图标用 `QPainter` 绘制，不使用图标库。时钟由一个浅色文字的深色半透明面板组成，上面显示时间，下面显示日期。`QTimer` 每秒更新这两个标签，这是 Qt 事件循环中的定时回调，不需要新建线程。

## 7. BalanceChart：继承、虚函数与多态

`BalanceChart` 公开继承 `QWidget`，因此它能像普通组件一样加入布局。父类提供虚函数 `paintEvent`，派生类重写它，并用 `override` 让编译器检查签名是否正确。

Qt 请求重绘组件时，通过虚函数机制调用我们的 `BalanceChart::paintEvent`，执行实际对象的绘制行为。这是程序中真正使用的运行时多态。

横轴按交易顺序排列，纵轴显示元。先计算余额最小值和最大值，将金额映射到绘图区坐标，再由 `QPainter` 画网格、线段和点。只有一个初始余额时画单点；余额不变时也保留纵轴范围，避免除以零。

## 8. 老师可能问的问题

| 问题 | 回答要点 |
| --- | --- |
| 为什么分成 BankCard 和 ATM？ | BankCard 表示一张卡的数据与操作；ATM 管理多张卡、登录状态、交易和保存。 |
| 封装在哪里？ | 银行卡数据为 private，通过成员函数访问和修改。 |
| 继承、多态在哪里？ | BalanceChart 继承 QWidget，重写 paintEvent，Qt 重绘时调用派生类实现。 |
| GUI 和控制台是否重复实现？ | 只重复各自的交互代码，核心业务共用 atm_core。 |
| 为什么不用 double 保存余额？ | 整数分可以精确进行金额加减。 |
| 取款为什么按 100 元倍数？ | 本项目采用的 ATM 模拟业务规则，不是所有银行设备的统一限制。 |
| 改密后如何保存？ | 修改当前卡后保存账户文件，保存失败恢复本次修改；重新登录使用新密码。 |
| 曲线数据从哪里来？ | 初始余额加当前账户每笔交易后的余额，取自实际保存的记录。 |
| 退卡是否销户？ | 否，只清除当前登录状态。 |
| 是否做了安全系统？ | 这是课程模拟，只有正常业务检查和文件错误处理，密码文本保存。 |
| 如何证明重启恢复？ | 测试另启控制台进程读取同一文件，演示也重新加载文件显示余额和记录。 |
| 为什么要测试？ | 确认输入错误不会改变余额、改密和保存生效、两个界面规则一致。 |

理解代码时优先阅读核心类，再阅读控制台，最后学习 Qt。`tests` 是验证辅助代码，可以在理解业务后再看。
